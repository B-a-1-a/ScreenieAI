# IdeaForge — Gemini Hackathon Build Plan (24 Hours)

## App Concept

A Tauri desktop app for project planning. Users describe their app idea, an AI agent (Gemini) asks clarifying questions, researches a dev plan, and generates structured deliverables — while the user optionally draws wireframes on a whiteboard canvas. Nano Banana generates polished whiteboard-style diagrams from descriptions. Outputs are saved to the filesystem and can be opened directly in Cursor, VS Code, or other AI-powered IDEs.

### Screen Types

Screens can be one of two types:
- **Visual** — contains a whiteboard wireframe (drawn by user OR generated by Nano Banana)
- **Info** — contains structured text info about your app (feature spec, tech stack, app flow, etc.)

### Key UI Behaviors

1. **Left sidebar (Screens panel)** — lists all screens in the project. Click to navigate the whiteboard to that screen's position. (+) button adds a new screen.
2. **Center (Whiteboard)** — infinite canvas. Each "screen" occupies a region. User can draw freely. Clicking a screen in the sidebar snaps/pans the whiteboard to focus on it.
3. **Top-right (Info panel)** — shows metadata and description for the currently selected screen. Editable.
4. **Bottom-right (Chat panel)** — contextual chat scoped to the selected screen. "Add a forgot password link" updates that screen's description and optionally regenerates its wireframe.

## Gemini API Integration

### Text generation (planning, chat, specs)

```typescript
// src/lib/gemini.ts
import { GoogleGenAI } from '@google/genai'  // v1.40+ (GA since May 2025)

const ai = new GoogleGenAI({ apiKey: import.meta.env.VITE_GEMINI_API_KEY })

export async function chat(params: {
  messages: Array<{ role: 'user' | 'model'; text: string }>
  systemPrompt: string
}) {
  const response = await ai.models.generateContent({
    model: 'gemini-2.5-flash',  // 1M context window
    contents: params.messages.map(m => ({
      role: m.role,
      parts: [{ text: m.text }],
    })),
    config: {
      systemInstruction: params.systemPrompt,
    },
  })
  return response.text
}

// Send canvas screenshot + text for vision analysis
export async function analyzeCanvas(params: {
  imageBase64: string   // PNG from tldraw export
  prompt: string
}) {
  const response = await ai.models.generateContent({
    model: 'gemini-2.5-flash',
    contents: [{
      role: 'user',
      parts: [
        {
          inlineData: {
            mimeType: 'image/png',
            data: params.imageBase64,
          },
        },
        { text: params.prompt },
      ],
    }],
  })
  return response.text
}
```

### Nano Banana image generation (wireframes)

```typescript
// src/lib/nanoBanana.ts
import { GoogleGenAI } from '@google/genai'

const ai = new GoogleGenAI({ apiKey: import.meta.env.VITE_GEMINI_API_KEY })

export async function generateWireframe(params: {
  screenName: string
  description: string
  appContext: string   // high-level app description for consistency
}): Promise<{ image: Uint8Array; text: string }> {
  const prompt = `Create a clean, hand-drawn whiteboard-style wireframe for a mobile/web app screen.

App context: ${params.appContext}
Screen name: "${params.screenName}"
Screen description: ${params.description}

Requirements:
- Draw it as a UI wireframe on a whiteboard with neat labels
- Include all UI elements mentioned in the description
- Use clean lines, boxes for inputs, circles for buttons
- Add text labels for each element
- Use a white/light background like a real whiteboard
- Include the screen name as a title at the top
- Make it look like a product designer's whiteboard sketch`

  const response = await ai.models.generateContent({
    model: 'gemini-2.5-flash-image',
    contents: [{ role: 'user', parts: [{ text: prompt }] }],
    config: {
      responseModalities: ['TEXT', 'IMAGE'],
    },
  })

  let image: Uint8Array | null = null
  let text = ''

  for (const part of response.candidates[0].content.parts) {
    if (part.text) {
      text = part.text
    } else if (part.inlineData) {
      // Decode base64 image data
      const binaryStr = atob(part.inlineData.data)
      const bytes = new Uint8Array(binaryStr.length)
      for (let i = 0; i < binaryStr.length; i++) {
        bytes[i] = binaryStr.charCodeAt(i)
      }
      image = bytes
    }
  }

  return { image: image!, text }
}

// Edit an existing wireframe based on chat feedback
export async function editWireframe(params: {
  existingImageBase64: string
  editInstruction: string
  screenName: string
}): Promise<{ image: Uint8Array; text: string }> {
  const response = await ai.models.generateContent({
    model: 'gemini-2.5-flash-image',
    contents: [{
      role: 'user',
      parts: [
        {
          inlineData: {
            mimeType: 'image/png',
            data: params.existingImageBase64,
          },
        },
        {
          text: `This is the current wireframe for the "${params.screenName}" screen. 
Please modify it: ${params.editInstruction}
Keep the same whiteboard sketch style. Return the updated wireframe.`,
        },
      ],
    }],
    config: {
      responseModalities: ['TEXT', 'IMAGE'],
    },
  })

  // ... same parsing as above
}
```

## Tauri Backend (Rust) — Minimal

Same thin Rust layer as before — no changes needed for Gemini vs Claude:

```rust
// src-tauri/src/lib.rs
use std::fs;
use std::path::PathBuf;
use std::process::Command;

#[tauri::command]
fn save_file(path: String, content: String) -> Result<(), String> {
    let path = PathBuf::from(&path);
    if let Some(parent) = path.parent() {
        fs::create_dir_all(parent).map_err(|e| e.to_string())?;
    }
    fs::write(&path, &content).map_err(|e| e.to_string())
}

#[tauri::command]
fn save_binary(path: String, content: Vec<u8>) -> Result<(), String> {
    let path = PathBuf::from(&path);
    if let Some(parent) = path.parent() {
        fs::create_dir_all(parent).map_err(|e| e.to_string())?;
    }
    fs::write(&path, &content).map_err(|e| e.to_string())
}

#[tauri::command]
fn open_in_ide(path: String, ide: String) -> Result<(), String> {
    let cmd = match ide.as_str() {
        "cursor" => "cursor",
        "vscode" => "code",
        "antigravity" => "antigravity",
        "windsurf" => "windsurf",
        _ => return Err(format!("Unknown IDE: {}", ide)),
    };
    Command::new(cmd).arg(&path).spawn()
        .map_err(|e| format!("Failed to open {}: {}", ide, e))?;
    Ok(())
}

#[tauri::command]
fn get_documents_dir() -> Result<String, String> {
    dirs::document_dir()
        .map(|p| p.to_string_lossy().to_string())
        .ok_or_else(|| "Could not find Documents directory".to_string())
}

#[tauri::command]
fn detect_ides() -> Vec<String> {
    let mut found = vec![];
    for (name, cmd) in [
        ("cursor", "cursor"), ("vscode", "code"),
        ("antigravity", "antigravity"), ("windsurf", "windsurf"),
    ] {
        if Command::new("which").arg(cmd).output()
            .map(|o| o.status.success()).unwrap_or(false) {
            found.push(name.to_string());
        }
    }
    found
}

#[tauri::command]
fn load_project(path: String) -> Result<String, String> {
    fs::read_to_string(&path).map_err(|e| e.to_string())
}

#[tauri::command]
fn list_projects() -> Result<Vec<String>, String> {
    let docs = dirs::document_dir()
        .ok_or("No documents dir")?;
    let ideaforge_dir = docs.join("IdeaForge");
    if !ideaforge_dir.exists() {
        return Ok(vec![]);
    }
    let mut projects = vec![];
    for entry in fs::read_dir(&ideaforge_dir).map_err(|e| e.to_string())? {
        let entry = entry.map_err(|e| e.to_string())?;
        if entry.file_type().map(|t| t.is_dir()).unwrap_or(false) {
            projects.push(entry.file_name().to_string_lossy().to_string());
        }
    }
    Ok(projects)
}

pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_dialog::init())
        .plugin(tauri_plugin_fs::init())
        .plugin(tauri_plugin_shell::init())
        .invoke_handler(tauri::generate_handler![
            save_file, save_binary, open_in_ide,
            get_documents_dir, detect_ides,
            load_project, list_projects
        ])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

## Whiteboard + Screens Architecture

The key UX challenge: how do screens relate to the whiteboard canvas?

### Approach: Screens as positioned regions on tldraw

Each screen gets a **frame** on the tldraw canvas at a specific (x, y) position. tldraw supports frames natively — they're labeled rectangular regions.

```typescript
// When a new screen is added or auto-generated:
function addScreenToCanvas(editor: Editor, screen: AppScreen) {
  const frame = editor.createShape({
    type: 'frame',
    x: screen.canvasRegion?.x ?? nextAvailableX(),
    y: screen.canvasRegion?.y ?? 0,
    props: {
      w: 400,
      h: 700,  // phone-sized frame
      name: screen.name,
    },
  })

  // If we have a Nano Banana wireframe, add it as an image inside the frame
  if (screen.wireframeBase64) {
    const asset = editor.createAssets([{
      type: 'image',
      id: `asset:${screen.id}`,
      typeName: 'asset',
      props: {
        src: `data:image/png;base64,${screen.wireframeBase64}`,
        w: 400,
        h: 700,
        name: `${screen.name}-wireframe`,
        mimeType: 'image/png',
        isAnimated: false,
      },
    }])

    editor.createShape({
      type: 'image',
      parentId: frame.id,
      x: 0, y: 0,
      props: { w: 400, h: 700, assetId: `asset:${screen.id}` },
    })
  }
}

// Navigate to a screen when clicked in sidebar
function focusScreen(editor: Editor, screen: AppScreen) {
  const region = screen.canvasRegion
  if (region) {
    editor.zoomToBounds({
      x: region.x - 50,
      y: region.y - 50,
      w: region.width + 100,
      h: region.height + 100,
    })
  }
}
```

### User can draw freely

Since tldraw is the canvas, the user can draw arrows between screens, add sticky notes, annotate wireframes, sketch their own layouts — all natively supported. The Nano Banana wireframes are just images placed on the canvas that coexist with the user's own drawings.

## Risk Mitigation

| Risk | Mitigation |
|------|------------|
| **Nano Banana rate limits** | Use `gemini-2.5-flash-image` (faster, cheaper). Queue wireframe generation. Don't regenerate unless explicitly requested. |
| **Nano Banana wireframe quality** | The model is excellent at whiteboard-style diagrams. Prompt engineering is key — specify "whiteboard wireframe" style. If quality varies, cache good results. |
| **Gemini JSON output reliability** | Use structured prompting with examples. Parse with try/catch and retry. Consider Gemini's JSON mode if available. |
| **tldraw + frames complexity** | Start without frames — just place wireframe images at fixed coordinates. Add frame containers only if time permits. |
| **Tauri Rust issues** | Rust code is copy-paste ready. If compile errors, temporarily skip filesystem commands and use browser downloads as fallback. |

## Getting Started

```bash
# 1. Install Rust (if needed)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# 2. Create project
npm create tauri-app@latest ideaforge -- --template react-ts
cd ideaforge

# 3. Install frontend deps
npm install tldraw zustand @google/genai
npm install -D tailwindcss @tailwindcss/vite

# 4. Install Tauri plugins
cd src-tauri
cargo add dirs tauri-plugin-dialog tauri-plugin-fs tauri-plugin-shell
cd ..

# 5. Set up env
echo "VITE_GEMINI_API_KEY=your_key_here" > .env

# 6. Test it runs
npm run tauri dev

# 7. Start building — begin with ProjectSelector page
```
